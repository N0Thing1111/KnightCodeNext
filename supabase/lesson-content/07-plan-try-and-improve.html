1. Programming logic: combine ideas into a justified plan

Solving a larger problem means selecting and combining sequences, conditions, updates and loops. Decomposition means breaking the goal into smaller tasks that you can explain and test separately.

Identify inputs, expected outputs and rules. Ask which work happens once, which repeats, and which depends on a condition. In the game, identify mechanisms that must change before a later route is possible.

2. Plan before writing the complete program

Consider a parcel counter. Read the parcel count and one whole-number weight per parcel. A weight of at least 10 earns 3 points; a lighter parcel earns 1 point. Print total points once. Assume nonnegative inputs.

  • Start the points total at zero.
  • Repeat once per parcel: read its weight, choose the appropriate points, and add them.
  • After all parcels, print the total.

A sequence handles setup and output, a loop handles the parcels, and a decision handles the rule for each parcel. The challenge is placing familiar features correctly.

3. Trace a decision inside a loop

Python example - use the Python editor, not the game terminal

parcels = int(input())
points = 0
for parcel in range(parcels):
    weight = int(input())
    if weight >= 10:
        points = points + 3
    else:
        points = points + 1
print(points)

9
10
12

Output

The loop body is indented four spaces. The if/else bodies are indented eight spaces because they are inside a decision inside a loop. The final print returns to the left margin and runs after all passes.

  • Weight 9: false branch, points becomes 1.
  • Weight 10: true branch, points becomes 4.
  • Weight 12: true branch, points becomes 7.

4. Debug the cause, not just the final number

Compare the intended trace with the actual result and find the first mismatch. Ask:

  • Initialization: should any points exist before a parcel is read? Starting at 1 creates an extra point even for zero parcels.
  • Repetition count: does the program request exactly one weight per parcel? range(parcels + 1) requests an extra input.
  • Boundary: which category owns weight 10? Using > instead of >= puts it in the wrong category.

Fix a cause, rerun the failing case, then test another case to check that the change did not break a correct result. A syntax error prevents execution; a logic error may produce readable but incorrect output. Matching output alone does not explain why the approach works.

5. Choose tests that challenge your reasoning

Test zero parcels, one below the boundary, one at the boundary, and mixed weights. Predict the outputs before running. Zero checks setup and loop count; the boundary checks the comparison; mixed weights check accumulation across both branches.

If an activity reports that it requested more input than an example supplies, inspect input calls and loop passes. Do not add arbitrary answers just to finish. If the numbers are correct but a check differs, also compare required text and line breaks.

6. Connect combined Python logic to a game plan

Choose the structure from the problem. Python variables track numerical state; game actions track position and mechanisms. Game commands are custom commands, so use them in the game terminal rather than pasting the Python parcel program there.

For this practice example, assume two right moves are clear. After them, up is open; right remains open after moving up. No goal ends the program early. Predict the full route:

KnightCode example - a small practice situation, not a full level solution

repeat(2):
    move(right)
if can(up):
    move(up)
else:
    move(down)
move(right)
  1. The loop performs right twice, changing the starting position for the decision.
  2. The upward check is true in the stated situation, so up runs and down is skipped.
  3. The final right move is outside the decision, so it runs afterwards.

Check your reasoning: The action sequence is right, right, up, right. If up were blocked after the loop and down were clear, the sequence would instead be right, right, down, right. The final right move would also need to be possible from that alternate position.

This is a small example of combining structures, not a full solution for your final game room. Map each part of your actual plan to the actual layout.

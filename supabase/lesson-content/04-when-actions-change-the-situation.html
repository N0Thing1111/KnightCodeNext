1. Programming logic: later actions depend on the current state

State means the facts describing a program or room at a particular moment. A Python variable might hold the battery charge. Game state includes the knight's position, crates, and whether a door is open. An action changes these facts, so a later decision must use the updated situation.

A dependency means one step needs another first. Charging before checking energy can change the answer, just as activating a button before crossing can make a route possible.

2. Read an update from right to left

Python example - use the Python editor, not the game terminal

charge = 6
recharge = 10
charge = charge + recharge
print(charge)

Output

16

For charge = charge + recharge, evaluate the right side using the old values: 6 + 10 is 16. Then assign 16 to charge. This is an update, not a mathematical claim that charge equals charge plus 10 forever. Later uses of charge see 16 until another assignment changes it.

3. Update first, then decide

Python example - use the Python editor, not the game terminal

charge = int(input())
recharge = int(input())
cost = 15
charge = charge + recharge
if charge >= cost:
    charge = charge - cost
    print(charge)
else:
    print("Wait")
    print(charge)

Example inputs, in order (one answer per input request)

6
10

Output

1

Trace: charge begins at 6, becomes 16 after recharging, passes the cost check, and becomes 1 after use. Checking the original 6 before recharging would reject an action the updated charge can support. The order is part of the solution.

4. Trace both outcomes and preserve the right value

With inputs 2 and 3, the updated charge is 5. It cannot cover cost 15, so output Wait and 5. Do not subtract the cost in that branch. With inputs 5 and 10, all 15 units can be used and the result is 0. A zero final value is not itself a failure.

On paper, label the starting value, value after the update, condition result and final value. Find the first difference from that trace rather than adding extra operations at the end.

5. Connect value updates to room updates

The Python example changes numbers. In the game, movement may activate a mechanism and change a later path check. Python variables do not directly operate game doors; the shared skill is following state over time.

For this small example only, suppose one right move activates an ordinary button. Once pressed, it opens the passage directly above the knight's new position. Both movements have been checked against this imagined layout.

KnightCode example - a small practice situation, not a full level solution

move(right)
if can(up):
    move(up)
  1. Move right onto the button. This changes the room.
  2. At the new position, check the upward passage.
  3. If that movement is now possible, move up.

Checking up before the right move would ask about the old position and old room state. Even the same direction name can refer to a different neighboring space after movement. Explain where and when a check happens, not just which word it contains.

6. Distinguish a lasting change from a held condition

  • Ordinary button: once activated, its linked door stays open when the activating object leaves.
  • Pressure plate: its linked door stays open only while an allowed object remains on the plate. When nothing holds it, the door closes.

A pressure plate is not simply an ordinary button with a short timer. What matters is whether it is still held. Standing on a plate can make the door open now without guaranteeing that the door will be open when you reach it.

Ask two different questions: Is the route open at this moment? Will the action I take next keep it open? The second question is what makes the plan reliable.

7. Use a crate to keep a required fact true

The knight pushes a crate by moving toward it. There is no separate push command in these lessons. The crate needs space to move into; a crate blocked against a wall cannot simply be pushed through it.

For a plate that accepts crates, leaving the crate on the plate can keep the door open while the knight leaves. Some switches have different activation rules, so inspect the level rather than assuming every object can activate every switch.

  1. Reach the correct side of the crate.
  2. Push it onto the intended crate-sensitive plate.
  3. Leave it there while the knight takes the opened route.

Throughout the crossing, the required fact is: the plate remains held. You may hear this described as a condition that must stay true. The reasoning matters more than the term. Moving the crate again can undo the useful state.

1. Programming logic: repeat a known amount of work

A loop repeats a group of instructions. Use a fixed-count loop when you know how many times the group should run. First identify the repeated work and count; do not use a loop only to make code shorter.

An iteration is one pass through the body. Count iterations separately from instructions: three passes through a two-action body perform six actions. Instructions within each pass still run in order.

2. Use for and range in Python

Python example - use the Python editor, not the game terminal

for step in range(3):
    print(step)
print("Finished")

Output

0
1
2
Finished

range(3) supplies 0, 1 and 2: three values, with 3 excluded. On each pass, step receives the next value and the indented body runs. The name step is a variable you choose. The final print is outside the loop and runs once. With range(0), the body runs zero times.

3. Keep a running total

An accumulator stores a result built over repeated steps. Begin a sum at 0 before the loop. Each pass adds the next value to the existing total.

Python example - use the Python editor, not the game terminal

count = int(input())
distance = 0
for segment in range(count):
    length = int(input())
    distance = distance + length
print(distance)

Example inputs, in order (one answer per input request)

3
2
4
1

Output

7

This totals route-segment lengths. The first input counts segments; it is not a length to add. Remaining answers are read inside the loop, one per pass. For count 3, distance changes from 0 to 2 to 6 to 7.

4. Decide what repeats and what happens once

  • Before the loop: read the count and initialize the accumulated value.
  • Inside the loop: read the next measurement and update the total.
  • After the loop: print the final answer once.

If distance were reset to 0 inside every pass, earlier measurements would be lost. If print were inside the loop, it would display partial totals 2, 6 and 7 instead of only 7. Reading a measurement only before the loop could reuse one value instead of reading the next.

Test zero, one and several segments. Zero tests initialization and skipped repetition; one tests a single pass; several reveal errors that overwrite earlier values.

5. Connect Python for to the game repeat command

Python uses for step in range(count): for known-count repetition. KnightCode uses its custom repeat(count):. They share the idea of repeating a body, but their spellings are not interchangeable. There is no built-in Python repeat() command for this activity.

KnightCode example - a small practice situation, not a full level solution

move(right)
move(right)
move(right)

Assume all three movements are possible and the level does not end during them. This sequence performs the same action three times. We can express that repeated part as:

KnightCode example - a small practice situation, not a full level solution

repeat(3):
    move(right)

The number 3 is the repetition count. The indented line is the loop body: the instruction that runs on each repetition. After the third repetition, execution continues after the loop.

The knight still performs three moves. The loop saves repeated writing, not physical movement. It also does not automatically check whether a wall is in the way.

6. A repeated group can contain more than one action

KnightCode example - a small practice situation, not a full level solution

repeat(2):
    move(right)
    move(up)

Both indented instructions belong to the body. Each repetition performs right and then up. The expanded order is right, up, right, up. It is not right, right, up, up.

Two repetitions of a two-action body produce four movement actions. Keep these quantities separate: number of passes and number of actions inside each pass.

A block is repeated as a unit, but instructions within it still run in order. A loop does not remove the sequence rules you already learned.

7. Use repetition in your levels

  • Do It Again: find the right-and-up pattern, count its repetitions, and trace the position after each pair.
  • Repeat, Then Turn: separate the repeated approach from the turn, button action and remaining route.

Before Run, expand the loop aloud or on paper. After Run, compare the movement pattern. If it differs, inspect the body and count separately. A loop that finishes is not necessarily a loop that reaches the goal.

8. Prepare for the Python activity

In Total several items, the repeated value is a price rather than a route length. Read how many items there are, then exactly that many prices. Build the total across passes, and print only the final total.

Do not write three separate price inputs just because one example has three items. The count controls how many inputs are needed. With zero items, there are no price inputs and the initialized total is still a valid result.

9. Activity inputs and expected output

Total several items: Read how many items there are. Then read one whole-number price for each item. Use a for loop to add all prices and print only the final total. Zero items must produce 0. Do not write one separate input line for every example item: the loop should work for any nonnegative count.

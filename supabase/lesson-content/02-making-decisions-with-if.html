1. Programming logic: decide whether an action is needed

A condition is a question with a true-or-false answer. An if statement runs its body only when that answer is true; if false, execution continues after the body. Use the input and variables from Lesson 1 to represent the situation.

Before coding, state the rule in words: when is the action needed, and what should happen regardless of the answer? A condition asks a question; an action changes or displays something.

2. Write the question precisely in Python

Comparison operators express questions: < means less than, > greater than, <= less than or equal to, >= greater than or equal to, == equal to, and != not equal to. Assignment = stores a value; comparison == tests equality.

Python example - use the Python editor, not the game terminal

temperature = int(input())
if temperature > 30:
    print("Take a water break")
print("Reading recorded")

Example inputs, in order (one answer per input request)

32

Output

Take a water break
Reading recorded

3. Indentation shows what belongs to the decision

The colon : ends the if header. Indent its body by four spaces. The warning belongs to the decision; the final print aligns with if, so it runs afterward whether the condition was true or false. Python uses indentation to group instructions, not just to make code tidy.

If both prints were indented, a temperature of 20 would print nothing. If the warning had no indentation, the if statement would be incomplete and Python would report an indentation error. Valid indentation can also group the wrong actions: that is a logic problem.

4. Trace true, false, and the boundary

  • Input 32: 32 > 30 is true. Print the warning, then Reading recorded.
  • Input 20: false. Skip the warning but still print Reading recorded.
  • Input 30: false because the rule says above 30, not at least 30.

The boundary is where the decision changes. Testing 29, 30 and 31 checks both sides and the exact boundary. Predict each output first. One successful example does not establish that the rule is correct for all inputs.

5. Connect the Python decision to a game check

Python compares a value here; the game checks whether movement is possible. Both decide whether to execute an indented action. can(right) is game-specific, not a standard Python function. An open movement may still be the wrong route to the exit.

KnightCode example - a small practice situation, not a full level solution

if can(right):
    move(right)

Read this as: If moving right is possible now, move right. The word if introduces the decision. The condition is can(right). The colon begins the following group of instructions, and the spaces before the move show that it belongs to that group.

That indented group is called a block. Use four spaces in these examples. The layout matters because it shows which instructions depend on the answer. Learn to see the relationship: the movement belongs to the decision.

If the answer is false, the program skips this block. It does not automatically move left, wait for a door, or search for a different route.

6. Decide what belongs inside the block

KnightCode example - a small practice situation, not a full level solution

if can(right):
    move(right)
move(up)

The right move belongs to the decision. The up move lines up with if, so it is outside the block. Provided execution continues, the up move is attempted after either outcome. Assume the upward move is clear from both possible positions in this example.

  1. Right open: move right, then move up.
  2. Right blocked: skip moving right, then move up.

Now imagine indenting the final line by four spaces as well. Both movements would belong to the same decision. When the condition is false, both would be skipped. A small change in grouping can make a large change in the plan.

Also, one successful check of right does not prove that a later move up is safe. A condition only answers the question you asked.

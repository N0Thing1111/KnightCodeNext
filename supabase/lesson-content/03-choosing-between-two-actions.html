1. Give the program two planned choices

An if statement can run a block or skip it. Sometimes you need a planned action for both answers. If/else selects the if block when the condition is true and the else block when it is false.

else means otherwise. It does not mean try every direction until one works. You write the alternative yourself. Your goal is to explain why each choice is appropriate for the situation that selects it.

This lesson adds choice to a sequence. After the chosen block finishes, execution continues with the instructions after the whole decision.

2. State the assumptions before choosing

Imagine a practice junction. Moving right is our preferred route when it is open. If right is blocked, we have already checked the map and know that up is an available alternative. These assumptions are part of the example.

KnightCode example - a small practice situation, not a full level solution

if can(right):
    move(right)
else:
    move(up)

Right open gives true, so the right move runs and the else block is skipped. Right blocked gives false, so the up move runs instead. One branch is selected, not both.

else: lines up with if. Each movement is indented underneath its own branch. The layout tells you which result selects which instructions.

3. Trace the two paths through the same program

  1. Situation A: right is open. Check can(right), choose the if branch, move right, skip else, then continue.
  2. Situation B: right is blocked and up is open. Check can(right), choose the else branch, move up, then continue.

The program is the same in both situations. Its behavior changes because the answer to the condition changes. This is how a program can respond to different starting situations without someone manually choosing a different line each time.

If both directions are open, this program still chooses right. It does not choose randomly or compare which route is shorter. The preference is written into the condition and branches.

4. Else is an alternative, not a safety check

Suppose both right and up are blocked. The condition is false, so the example selects move(up). But choosing that line does not make the movement possible. The else branch does not secretly test up.

For a real room, use a known-safe alternative or check the alternative too. One way to check it is a decision inside the else block:

KnightCode example - a small practice situation, not a full level solution

if can(right):
    move(right)
else:
    if can(up):
        move(up)

This is a nested decision: a decision inside another decision. If both directions are blocked, neither movement runs. Read the spaces carefully: the up move belongs to the inner check, and the entire inner check belongs to else.

You do not need nesting for every puzzle. Use it only when the plan needs another question.

5. Ask the opposite question with blocked

blocked(right) asks whether moving right is blocked now. In the same unchanged situation, it gives the opposite answer to can(right). It checks movement rules, not just whether a tile looks like a wall.

KnightCode example - a small practice situation, not a full level solution

if blocked(right):
    move(up)
else:
    move(right)

Under our earlier assumption that up is a safe detour, this makes the same choice as the first example. When right is blocked, it chooses up. When right is open, it chooses right.

Notice that we changed the question and swapped the branch actions. Changing can to blocked without changing the branches would reverse the intended choice. Always translate the whole decision into plain words.

6. Read and predict the continuation

Assume the last left move is possible after either branch and no exit ends execution early. Predict the full sequence when up is open, then when up is blocked but right is open.

KnightCode example - a small practice situation, not a full level solution

if can(up):
    move(up)
else:
    move(right)
move(left)

Check your reasoning: Up open: up, then left. Up blocked: right, then left. The final left move is outside both branches, so it is attempted after the selected branch. In an open practice area, the second route returns to its starting horizontal position.

Why does the knight not run the right move after the up move in the first situation?

Check your reasoning: They belong to different branches of one if/else decision. Once the true branch is selected, the else branch is skipped.

7. Find and fix reversed logic

The intention is: if right is blocked, take a known-open upward detour; otherwise go right. A student writes:

KnightCode example - a small practice situation, not a full level solution

if blocked(right):
    move(right)
else:
    move(up)

Trace the blocked case before changing anything. Which instruction does it select? Does that match the intention?

Check your reasoning: When right is blocked, the condition is true and the program selects the right move. That contradicts the plan. Swap the branch actions: up belongs in the true branch and right belongs in else. Then check the open case too.

Do not judge a condition by whether it contains a familiar word. Judge it by which action its true answer selects.

8. Plan your own preference

At a practice junction, prefer left if it is possible. Otherwise, use a known-clear downward path. Write the decision, then explain what happens when both paths are open and when only down is open.

KnightCode example - a small practice situation, not a full level solution

if can(left):
    move(left)
else:
    move(down)

Check your reasoning: Both open: left is selected because it is the written preference. Only down open: the condition is false, so down is selected. If neither is open, the assumption about a safe alternative fails; this version does not solve that situation.

A useful explanation includes the limits of the plan. Saying when a solution does not work is part of understanding it.

9. A small connection to real code

Real Python example - read only; not a KnightCode command

score = 6
if score >= 5:
    print("Goal reached")
else:
    print("Keep practising")

The condition asks whether score is at least 5. With 6, only the first message appears. With 3, only the second appears. With exactly 5, the first appears because the check includes equality.

The shared idea is choosing one branch from two. The number check is different from a path check, but the decision structure is the same. You do not need Python syntax to explain the two possible outcomes.

10. Practise decisions in your levels

  • Right or Up?: state which direction your decision prefers and why that helps the route.
  • When the Answer Is No: explain the alternative before running the false case.
  • Is It Blocked?: translate blocked into a yes-or-no question and check which branch true selects.
  • Looks Can Be Misleading: distinguish a tile's appearance from whether movement is actually allowed.

A condition tests a local fact. It does not tell you whether a direction eventually reaches the exit. After choosing a branch, continue tracing the rest of the room.

11. Check your reasoning

  • Why does else not guarantee a safe movement?
  • How can both paths be open while only one branch runs?
  • What must change when you replace can with blocked but want the same choice?

Check your reasoning: Else selects the action you supplied without another automatic check. The condition determines the chosen branch even when both paths are possible. Reversing the question requires reversing the branch actions if you want to preserve the same behavior.

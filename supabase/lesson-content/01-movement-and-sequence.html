1. Programming logic: choose the steps and their order

Programming logic is the reasoning behind a solution: what information is needed, which steps change it, and why those steps reach the goal. An algorithm is that step-by-step plan. Python is the language we will use to express and test the plan. In the game, you apply the same reasoning to movement commands.

Start with the information given, write the steps in order, predict the result, then compare your prediction with a run. Correct spelling matters, but understanding why the steps work is the learning goal. You should be able to explain both a route and a calculation without guessing.

2. Variables remember the current values

A variable is a name that refers to a value. In length = 8, the equals sign assigns 8 to length. It does not ask whether two things are equal. Later lines can use that stored value. Names must be written consistently: length and Length are different names.

Python example - use the Python editor, not the game terminal

length = 8
pieces = 3
used = length * pieces
print(used)

Output

24

Trace the sequence: length becomes 8, pieces becomes 3, and used becomes 24. The * operator means multiplication. print(used) displays the value of used. print("used") would display the word used because quotation marks describe text, called a string.

3. Read input, process it, then display output

input() reads one answer as text. int(input()) converts that text to a whole number so arithmetic can use it. Enter valid whole numbers such as 3, without currency signs or extra words. Each call reads the next answer, so input order is part of the plan.

Python example - use the Python editor, not the game terminal

length = int(input())
pieces = int(input())
roll = 40
used = length * pieces
left = roll - used
print(used)
print(left)

Example inputs, in order (one answer per input request)

8
3

Output

24
16

This example measures ribbon. Calculate how much ribbon the pieces use, then subtract it from the roll. The - operator means subtraction. Each print() starts a new output line: used ribbon first, then what remains. A line beginning with # is a comment for people; Python does not execute it.

4. Trace and debug a sequence

Record the values after each step: length 8, pieces 3, roll 40, used 24, left 16. If left = roll - used came before used was first assigned, Python would report an error. If you wrote used = length + pieces, the program could run but calculate the wrong amount: a logic mistake.

Predict: what should change when the inputs become 5 and 4?

The used amount becomes 20 and the remainder becomes 20. The instructions stay the same; the inputs change. Do not replace the calculation with print(24): that only imitates one example.

5. Connect sequence to the game

Python variables track quantities; the game tracks the knight's position. In both, a step starts from the result of earlier steps. Game commands such as move(right) belong in the game terminal. They are not built-in Python functions, and Python input/print examples do not control the knight.

KnightCode example - a small practice situation, not a full level solution

move(right)
move(right)
move(up)

move asks the knight to move. The direction inside the parentheses tells it which way: up, down, left, or right. Here, the directions are fixed directions on the screen, not instructions to turn the knight first.

The three lines form a sequence. In this simple program, the first move happens before the second, and the second happens before the third. The knight does not understand the intended route unless your instructions describe it. A blocked move does not mean the game will invent a detour for you.

Use the game command spelling when typing. The important idea, however, is the relationship between an instruction and its result, not memorizing parentheses.

6. Order can change the route

Compare right, right, up with up, right, right. On an empty practice area, these can finish at the same position. That does not mean they are always interchangeable. They visit different positions on the way.

Suppose the space directly above the start is blocked, but the route right, right, up is clear. Starting with up now attempts a blocked movement. The same directions and the same number of instructions can produce a different journey because the order changed.

When comparing two plans, ask both questions: Do they finish in the same place? Can every intermediate step actually happen?

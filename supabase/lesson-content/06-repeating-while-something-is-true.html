1. Programming logic: let the current situation decide

A for/range loop is useful when you know the number of repetitions. A while loop checks a condition before each pass and repeats while it remains true. You may know the goal without knowing how many passes will reach it.

Plan the starting state, the condition for continuing, and the action changing the state. If the body never makes progress toward a false condition, the loop may not stop.

2. Trace a simple Python while loop

Python example - use the Python editor, not the game terminal

remaining = 3
while remaining > 0:
    print(remaining)
    remaining = remaining - 1
print("Finished")

Output

3
2
1
Finished

Check 3 > 0, print 3, update to 2, and return to the check. After printing 1, the update makes remaining 0. The next check is false, so skip the body and print Finished. Python does not keep the answer from the first check.

If remaining started at 0, the body would run zero times. An if checks once and runs its body at most once; while may run it many times.

3. Repeat input until a goal is reached

Python example - use the Python editor, not the game terminal

capacity = int(input())
filled = 0
pours = 0
while filled < capacity:
    amount = int(input())
    filled = filled + amount
    pours = pours + 1
print(filled)
print(pours)

Example inputs, in order (one answer per input request)

10
6
5

Output

11
2

This records water poured toward a positive capacity, assuming positive whole-number pours and that going over is allowed. The amount accumulated and number of pours are different quantities. After 6 and 5, filled is 11 and pours is 2. The next check is false, so no third pour is requested.

4. Choose a stopping rule that handles overshooting

filled < capacity continues only below the goal, so equality and overshooting both stop it. filled != capacity would remain true at 11 when capacity is 10. With positive pours, moving further upward cannot reach 10 again.

Positive inputs advance the total. Zero would not advance it; a negative value would move it backward. Follow the activity's stated valid inputs. If a program keeps requesting unexpected input, stop it and inspect the condition, update and indentation rather than supplying endless answers.

5. Connect the check-update cycle to the game

In Python, changing a value can make the condition false. In the game, moving changes the position from which the path is checked. can(right) is game-specific, not a built-in function in the Python editor.

KnightCode example - a small practice situation, not a full level solution

while can(right):
    move(right)
  1. Check can(right) from the current position.
  2. If true, run move(right).
  3. Return to the condition and check it from the resulting position.
  4. If false, skip the body and continue after the loop.

The check happens before the movement, including before the first one. The program does not move once just to find out whether it can move. The action changes the position, so the next check can produce a different answer.

The indented instructions are the body, just as with repeat. Every pass through the body follows its own sequence in order.

6. Continue after the loop deliberately

Suppose the corridor ends at a wall and an upward opening is available at that endpoint. The following program separates following the corridor from checking the turn.

KnightCode example - a small practice situation, not a full level solution

while can(right):
    move(right)
if can(up):
    move(up)

The if statement lines up with while, so it is outside the loop. It is reached after the rightward loop ends. The upward check is made at the final position, not after every right move.

If an upward side passage appears halfway along the corridor while right is still open, this simple while loop passes it. It checks only right. The stopping rule must match the part of the route you actually want.

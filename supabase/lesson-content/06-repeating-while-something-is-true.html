1. Let the situation decide whether to continue

repeat uses a count you choose in advance. A while loop asks a condition before each pass through its body. If the answer is true, it runs the body and checks again. If the answer is false, it leaves the loop.

This fits a plan such as "keep moving right while moving right is possible." You may not need to count the corridor first, but you still need to understand where the loop stops and what happens afterwards.

Your learning goal is to explain the repeated decision. A while loop is not a command that automatically solves an unknown room.

2. Read the check-action-check cycle

KnightCode example - a small practice situation, not a full level solution

while can(right):
    move(right)
  1. Check can(right) from the current position.
  2. If true, run move(right).
  3. Return to the condition and check it from the resulting position.
  4. If false, skip the body and continue after the loop.

The check happens before the movement, including before the first one. The program does not move once just to find out whether it can move. The action changes the position, so the next check can produce a different answer.

The indented instructions are the body, just as with repeat. Every pass through the body follows its own sequence in order.

3. Trace a short corridor

Imagine a clear straight corridor with exactly three successful right movements available before a wall blocks the next movement. Assume no exit or other event ends execution during this example.

  1. Check 1 is true. Move right for the first time.
  2. Check 2 is true from the new position. Move right for the second time.
  3. Check 3 is true. Move right for the third time.
  4. Check 4 is false at the blocked end. Do not move right again; leave the loop.

There were three movements and four checks. The final false check is how the loop discovers that another pass should not happen. Count checks separately from actions when tracing a while loop.

4. Include the case where the body never runs

Now put the knight where right is already blocked. The first check is false. The loop body runs zero times, and execution continues after the loop.

This is not an error. It is the expected result of checking before acting. A useful test set includes zero repetitions, one repetition, and several repetitions. Each tells you something different about the plan.

If the body contains an action that your later plan always requires, ask whether it is safe for that action to be skipped completely. Sometimes that action belongs before or after the loop instead.

5. Compare if, repeat and while

  • if can(right): checks once when reached and may perform its body once.
  • repeat(3): plans three passes through its body without using a path condition to choose the count.
  • while can(right): checks before every pass and keeps repeating only while its condition remains true.

On a corridor with exactly three available moves, repeat(3) and the simple rightward while loop can produce the same movements. If the corridor length changes, the fixed count stays three while the condition-controlled loop may perform a different number.

That does not make while always better. Choose according to the goal: "exactly three" and "as far as possible" are different requirements.

6. Continue after the loop deliberately

Suppose the corridor ends at a wall and an upward opening is available at that endpoint. The following program separates following the corridor from checking the turn.

KnightCode example - a small practice situation, not a full level solution

while can(right):
    move(right)
if can(up):
    move(up)

The if statement lines up with while, so it is outside the loop. It is reached after the rightward loop ends. The upward check is made at the final position, not after every right move.

If an upward side passage appears halfway along the corridor while right is still open, this simple while loop passes it. It checks only right. The stopping rule must match the part of the route you actually want.

7. Read and predict different starting situations

Use the previous program. In A, two right moves lead to a wall and up is open there. In B, right is blocked immediately and up is open at the start. In C, right and up are both blocked at the start. Predict the actions.

Check your reasoning: A: right, right, then up. B: the loop runs zero times, then the if selects up. C: the loop runs zero times and the if block is skipped, so neither movement runs. The same program responds differently because the checked facts differ.

In A, how many times is the rightward condition checked?

Check your reasoning: Three times: two true answers allow the two moves, and a final false answer ends the loop. The upward condition is a separate check.

8. Find a loop that cannot make progress

Imagine two adjacent open positions. The starting position has a clear path to its right. Both moves below succeed, and nothing else in the room changes:

KnightCode example - a small practice situation, not a full level solution

while can(right):
    move(right)
    move(left)

Trace one full pass. Where does it finish? What answer will the next condition get?

Check your reasoning: The body returns the knight to the starting position. Right is still open, so another pass repeats the same situation. The plan does not move toward making the condition false. The game may stop it with a safety limit, but that limit is not a correct solution.

If the intention was to reach the right-hand wall, remove the move that undoes the progress. Then explain why each successful right movement brings the knight closer to the blocked endpoint. Do not rely on a program being stopped for you.

9. Plan and justify a stopping rule

Write a program that follows an upward corridor while movement is possible, then attempts one right move only if right is open. Assume following the whole corridor is the intended first part of the route.

KnightCode example - a small practice situation, not a full level solution

while can(up):
    move(up)
if can(right):
    move(right)

Explain three things before running: what is checked repeatedly, what changes inside the loop, and what makes it stop. Then trace the case where up is blocked at the start.

Check your reasoning: The loop checks upward movement; its body changes the position upward; the blocked end eventually makes the condition false. If blocked initially, it performs no upward moves and immediately reaches the separate rightward check.

10. A small connection to real code

Real Python example - read only; not a KnightCode command

items_left = 3
while items_left > 0:
    print(items_left)
    items_left = items_left - 1
print("Finished")

This Python program displays 3, 2, 1, then Finished. Each repetition reduces the stored count. Once the count reaches 0, the next condition is false. If the subtraction were removed, the value would stay 3 and the condition would stay true.

The shared reasoning is termination: explain how the body moves the situation toward stopping. The subtraction is Python example code, not a command to enter in KnightCode.

11. Practise on your routes

  • Keep Going: identify the corridor's stopping point and the remaining route after it.
  • Check Again: explain how each movement changes where the next check happens.
  • Stop, Then Turn: keep the loop, button visit and final turn in the order the room needs.

Use the room rather than a guessed count to justify a while condition. Test the planned endpoint: stopping safely at the wrong location still leaves the goal unsolved.

12. Check your reasoning

  • Can a while body run zero times?
  • Why can three successful moves need four checks?
  • What is wrong with a loop that always returns to the same unchanged situation?

Check your reasoning: Yes: its first condition can be false. The extra check discovers that a fourth move should not happen. An unchanged situation can keep the condition true forever, so the plan needs an action that genuinely leads toward its intended stopping condition.
